# 构建与测试记录

2026-10-28，在 Ubuntu 24.04 / WSL2、项目 Pixi 锁定环境中执行，验证对象为 PR #2 的统一消息及仓储重构。

| 检查 | GCC 16.1.0 | Clang 21.1.8 |
|---|---|---|
| C++26 named modules + 真正的 `import std` | 通过 | 通过 |
| 原生测试（CTest） | 1/1 通过 | 1/1 通过 |
| 对应编译器 Python binding 测试 | 48/48 通过 | 48/48 通过 |

GCC 16.1 的导出兼容修复把 OpenCV / fmt 原始声明集中到适配模块，并在该版本的第三方头文件边界统一标准库全局声明。两种编译器都实际构建和导入工具链提供的 `std` 模块；Clang 不启用 GCC 兼容头文件中的前置处理。当前 CMake 的标准库模块支持仍标为实验性，会输出相应开发者警告。

已实际执行源码可编辑安装、`huoxing --help` 和 `examples/demo.py`。演示通过统一 `Message` 入口完成裁剪图与原图匹配（本次生成样例为 400 个内点），以及同一顶层资源包重复检测；两者均返回统一哈希和首次消息信息，演示数据库自动清理。

`clang-format 21.1.8 --dry-run --Werror` 对原生 `.cppm`、绑定和 C++ 测试通过。测试没有复用之前安装的另一编译器扩展，而是直接加载各自 `build/gcc`、`build/clang` 的产物。

原生测试覆盖 SHA-256、非空字符结尾的 `string_view` SQL/参数、SQLite 复制参数生命周期、图片匹配、持久化、并发登记，以及通过 `Repository` / `IDetector` 抽象接口注入后端并检测两种消息。

Python 测试覆盖：

- 裁剪、边框、水印、JPEG、组合修改及双向匹配；不同图案和小共同区域反例。
- 幂等、重启、群隔离、容量回滚、并发、无效输入和拒绝动图。
- AstrBot / MaiBot 模拟事件、最外层媒体处理，以及取消等待后的在途任务限制。
- 相同转发资源 ID、变化 ID 的相同卡片、空 ID、弱卡片证据不判为可靠重复。
- 节点对象一旦访问就报错，确认不读取整包内部节点。
- 两类消息的统一指纹、元数据独立性、字段边界编码、缺少内容时的事件哈希。
- 图片/转发重推时恢复已登记哈希，保留首次信息；旧数据补建统一索引仍指向首次记录。
- 图片和转发一起清理，统一索引与消息记录同时回滚。

不包含真实 QQ 账号、SnowLuma / NapCat 在线接入、真实群图片数据集评测或不同版本 AstrBot/MaiBot 的端到端验收。转发后资源 ID 是否变化仍需实机验证；自动测试不代表真实场景准确率或账号风控概率。CMake 允许 GCC >=16.1、Clang >=21，已实测版本仅为上表所列版本。
